# Knowledge Model — 知识体系与编码规则

> 结构：Subject → Module → Unit → KnowledgeNode → MicroSkill，另含 KnowledgePrerequisite。
> 教材：上海科学技术出版社 · 五·四学制。物理覆盖八、九年级，化学覆盖九年级。

---

## 1. 编码规则（冻结）

### 1.1 层级编码

每级用固定前缀 + 两位数字，逐级拼接，形成可读且稳定的 `code`：

```
Subject:      PH (物理) / CH (化学)
Module:       {SUBJECT}-{Mnn}            例 PH-M01
Unit:         {MODULE}-Unn               例 PH-M01-U01
KnowledgeNode:{UNIT}-Knn                  例 PH-M01-U01-K03
MicroSkill:   {NODE}-Snn                  例 PH-M01-U01-K03-S02
```

- `nn` 两位数字，从 01 起，同级内递增。
- 编码一经发布**不复用、不重排**；废弃节点用 `status=ARCHIVED`，不删除。
- `code` 唯一索引，作为业务层稳定标识；数据库主键仍为 UUID。

### 1.2 示例展开

```
PH (物理)
 └─ PH-M05 力与运动
     └─ PH-M05-U02 力
         └─ PH-M05-U02-K03 重力
             ├─ PH-M05-U02-K03-S01 重力的概念与方向
             ├─ PH-M05-U02-K03-S02 重力大小 G=mg
             └─ PH-M05-U02-K03-S03 重力作用点（重心）
```

### 1.3 前置依赖（KnowledgePrerequisite）

- 表结构：`(nodeId, prerequisiteNodeId, strength)`。
- `strength`：`HARD`（硬前置，未掌握不得推进复杂应用）/ `SOFT`（软前置，建议但不阻断）。
- 调度器在推进复杂 MicroSkill 前检查硬前置的掌握度；低于阈值（默认 60）则回退到前置微知识。

## 4. MicroSkill 设计模板

每个 MicroSkill 落地时必须包含：

```json
{
  "code": "PH-M05-U02-K03-S02",
  "name": "重力大小 G=mg",
  "context": "情境：为什么不同质量的物体落地快慢相近但重力不同",
  "coreConcept": "物体所受重力跟质量成正比，G=mg，g≈9.8N/kg",
  "formula": "G = m · g",
  "commonPitfalls": ["把质量 m 与重力 G 混用", "g 的单位取错", "忽略方向竖直向下"],
  "basicExample": "...（基础例题，含标准解析）",
  "estimatedMinutes": 5,
  "examWeight": 0.8,
  "repairability": 0.9
}
```

`examWeight`、`repairability` 供调度器 Priority 公式使用；阈值全部配置化（见 ALGORITHM.md）。

## 5. 覆盖能力自检

- **物理**：21 个 Module，约 90+ KnowledgeNode，覆盖指令列举的全部主题（测量、运动、声、光、透镜、密度、力、压强、浮力、机械、功/功率/效率、机械能、热学、电学、磁学、能源），含八年级完整内容 → **满足一模复习范围**。
- **化学**：13 个 Module，约 60+ KnowledgeNode，覆盖指令列举的全部主题 → **满足九年级完整范围**。
- **前置依赖**：通过 KnowledgePrerequisite 表达，硬/软两级，支撑"前置未掌握不强制推进" → **满足**。
- **题目映射**：Question 通过 QuestionKnowledge 关联到 KnowledgeNode 与 MicroSkill，支持主/次知识点 → **满足**（Phase 3 落地）。
